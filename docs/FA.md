# کدچ آی‌دی‌ای

هدف محصول: محیط توسعهٔ دسکتاپ متن‌باز بر پایهٔ Code-OSS که گفت‌وگو با ایجنت، کد، دانش پروژه و بازبینی تغییرات را در یک فضای مشترک قرار دهد. هویت بصری از لوگوی هندسی کدچ، سبز سلطنتی و طلایی گرفته شده و برای کار طولانی به سبز تیره، سبز روشن و طلایی ملایم تبدیل شده است.

## وضعیت واقعی این نسخه

این نسخه یک افزونهٔ قابل اجرا برای VS Code / Code-OSS، هارنس اولیه، پیش‌نمایش تعاملی رابط و مسیر آماده‌سازی سورس توزیع مستقل است. هنوز فایل نصب مستقل Codech IDE، اجرای پلاگین‌های Obsidian، همهٔ قابلیت‌های PyCharm Professional یا یک سیستم ایجنتیک کامل و پایدار تولیدی نیست.

## شروع استفاده

فایل VSIX را از بخش Install from VSIX نصب کن و دستور `Codech: Open Workbench` را اجرا کن. برای محیط توسعه، `npm install`، سپس `npm run dev` را اجرا کن. پروفایل توسعه مستقل است. تم `Codech Forest` هم در انتخابگر تم میزبان وجود دارد.

گفت‌وگو در صفحهٔ اصلی ادیتور باز می‌شود. انتخاب فایل یا Open diff، ادیتور واقعی کد را کنار گفت‌وگو باز می‌کند. یادداشت‌ها در `.codech/knowledge` ذخیره می‌شوند و لینک‌هایی مثل `[[Architecture]]` دارند. برای worktree، پروژه باید Git و حداقل یک commit داشته باشد.

## اتصال هوش مصنوعی

دو مسیر وجود دارد:

- **ChatGPT / Codex:** از Codex App Server رسمی استفاده می‌کند. ورود حساب در فضای مستقل کدچ انجام می‌شود. CLI باید جداگانه نصب باشد. مدل و سقف استفاده به دسترسی حساب بستگی دارد.
- **OpenAI API:** کلید در SecretStorage میزبان ذخیره می‌شود. ابزارهای آماده برای فایل، جست‌وجو، بررسی Git، پیشنهاد تغییر و اجرای چک مشخص وجود دارند. تغییر پیشنهادی پس از بررسی تو اعمال می‌شود. هزینه و شرایط API مستقل از مسیر Codex هستند.

انتخاب Terra به معنی تضمین دسترسی حساب به آن نیست. نمایش مدل در فهرست هم مجوز استفاده را ثابت نمی‌کند. این نسخه هیچ توکن یا نشست ورود برنامهٔ دیگری را استخراج نمی‌کند.

## طراحی هارنس

هارنس باید زمینهٔ لازم را با حجم محدود پیدا کند، ابزارهای آماده داشته باشد، وضعیت کار را حفظ کند و شواهد بررسی ارائه دهد. در این نسخه اسکن محدود فایل‌ها، انتخاب README و AGENTS و دانش محلی، و ابزارهای آماده پیاده شده‌اند. نمایهٔ افزایشی پایدار، بازیابی معنایی خودکار و سنجش دقیق صرفه‌جویی هنوز مراحل بعد هستند. عددی برای درصد کاهش توکن یا برابری کیفیت مدل‌ها ادعا نشده است.

برای هر کار می‌توان worktree ساخت و یک گفت‌وگو را به آن متصل کرد. تأیید هر فایل به محتوای بررسی‌شده گره می‌خورد؛ اگر فایل تغییر کند تأیید معتبر نیست. این تأییدها محلی و موقت‌اند. دکمهٔ commit با درخواست خودت، مسیرهای تأییدشده را در index جدا ثبت می‌کند و فایل‌های staged نامرتبط را نگه می‌دارد. push و merge خودکار وجود ندارد.

## گراف و حافظه

گراف کد از importها و گراف دانش از wikilinkها ساخته می‌شود. Graphiti اتصال جداگانهٔ MCP محلی برای جست‌وجوی حافظهٔ معنایی دارد و به سرویس اختیاری نیاز دارد. ورود ChatGPT ایجنت، هزینه یا احراز هویت استخراج دانش و embedding در Graphiti را تأمین نمی‌کند. تنظیم مدل محلی هم باید جداگانه آزموده شود.

## افزونه‌ها و تجربهٔ PyCharm

افزونه‌های VS Code در میزبان اصلی و نصب VSIX پشتیبانی می‌شوند؛ در توزیع مستقل Open VSX مبناست و مجوز هر افزونه باید رعایت شود. پلاگین Obsidian برای اجرا به API واقعی آن نرم‌افزار نیاز دارد؛ این نسخه فقط manifest را بررسی می‌کند و اجرای آن را وعده نمی‌دهد. برای تجربهٔ PyCharm نیز میانبرها، تنظیمات Django، دیباگ، تست، ابزار دیتابیس و refactoring باید موردی پیاده‌سازی و آزمایش شوند.

جزئیات محدوده و مراحل بعد در [معماری](ARCHITECTURE.md)، [سازگاری](COMPATIBILITY.md) و [نقشهٔ توسعه](ROADMAP.md) آمده است.
